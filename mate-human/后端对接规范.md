# Mate Human 前端能力清单与后端对接规范

> 本文档依据前端工程 `mate-human/CubismSdkForWeb-5-r.4/Samples/TypeScript/Demo/src/` 实际代码整理。
> 后端只要按本文档实现，即可 100% 覆盖前端全部能力。**文档中标 ⚠️ 的均为前端代码中明确提醒过的坑，后端必须严格遵守。**

---

## 一、总体架构

```
┌──────────────┐   WebSocket(ws://127.0.0.1:10002)   ┌──────────────────┐
│   后端         │ ─────────────────────────────────→ │  Live2D 前端      │
│ (LLM/TTS/情感) │                                    │  - 语音播放        │
│              │ ◄─── {Username, Output} 连接握手 ────│  - 口型同步        │
│              │    音频消息 / 口型 / 动作指令          │  - 表情切换        │
└──────────────┘                                    │  - 动作驱动        │
                                                     └──────────────────┘
```

- 前端只做**渲染与交互**，后端负责：对话（LLM）、语音合成（TTS）、情感分析、动作语义决策。
- 前端硬编码连接地址：`ws://127.0.0.1:10002`（见 `lappmodel.ts` 与 `fayclient.ts`）。

## 二、WebSocket 连接规范

### 1. 连接地址
- **`ws://127.0.0.1:10002`**（前端硬编码，后端必须监听 10002 端口的 human endpoint）。

### 2. 连接握手 ⚠️
前端连接建立后**立即发送**第一条消息：

```json
{ "Username": "User", "Output": true }
```

⚠️ **提醒**：`Username` 必须默认接受 `"User"`（前端注释原文："使用 'User' 作为 username，与 Fay 默认用户名匹配"）。后端不能因为不认识该用户名而断开连接。

### 3. 重连机制（前端行为，后端需容忍）
- 前端断线后自动重连：指数退避 `1s → 2s → 4s → ...`，上限 30s，最多 **5 次**。
- 后端应允许客户端频繁重连，不要对短时间内重复连接做封禁。

### 4. 消息格式
- 全部为 **JSON 文本帧**（前端 `JSON.parse(event.data)`，解析失败会报错跳过）。
- 前端只解析消息，**不发送任何请求/应答类协议**（除握手消息外，前端不发别的）。

## 三、后端 → 前端 消息结构（核心协议，必须严格匹配）

前端接口定义见 `fayclient.ts`，完整结构如下：

```json
{
  "Topic": "human",
  "Username": "User",
  "robot": "optional",
  "Data": {
    "Key": "audio",
    "Text": "这句话的文本",
    "Value": "可选",
    "HttpValue": "http://127.0.0.1:5000/audio/xxx.wav",
    "Type": "可选",
    "Time": 0,
    "IsFirst": 1,
    "IsEnd": 0,
    "Lips": [
      { "Lip": "sil", "Time": 80 },
      { "Lip": "aa",  "Time": 120 }
    ],
    "Sentiment": 0.7,
    "MotionNo": 3,
    "MotionGroup": "TapBody",
    "Action": {
      "code": "guidance.invite",
      "behavior": "invite",
      "affect": "warm",
      "intensity": 0.74,
      "priority": 82,
      "matchedKeywords": ["请"],
      "sentimentHint": 0.5
    }
  }
}
```

### 字段说明表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `Topic` | string | 是 | 固定为 `"human"`（前端未校验，但按 Fay 协议保持） |
| `Username` | string | 是 | 与握手一致，`"User"` |
| `Data.Key` | string | 是 | **`"audio"` 时前端才走音频播放流程**，其他值前端会忽略 |
| `Data.Text` | string | 是 | 当前分片的文本，前端仅用于日志/调试 |
| `Data.HttpValue` | string | 条件 | ⚠️ 音频 URL，**HTTP GET 可访问**（见第六节）。无此字段则前端只驱动口型、不播声音 |
| `Data.IsFirst` | number | 是 | ⚠️ **`1` 表示新音频流的第一个分片**（前端据此清空播放队列、streamId+1）。建议第一个分片必为 1 |
| `Data.IsEnd` | number | 是 | ⚠️ **`1` 表示整段对话结束**（前端恢复默认微笑表情 F01，让动作自然播完）。最后一个分片必须为 1 |
| `Data.Lips` | array | 是 | 口型数据（见第四节） |
| `Data.Sentiment` | number | 否 | 情感值，范围 **-2 ~ +2**（见第五节） |
| `Data.MotionNo` | number | 否 | ⚠️ 动作编号，**从 1 开始**（前端会减 1 转为 0 基索引），属于兼容层（见第七节） |
| `Data.MotionGroup` | string | 否 | 动作组名，缺省时前端用 `"TapBody"`（见第七节） |
| `Data.Action` | object | 否 | 语义动作（**推荐使用，优先级最高**，见第五节） |
| `Data.Action.code` | string | 是 | 动作代码，如 `"guidance.invite"`，前端仅用于日志 |
| `Data.Action.behavior` | string | 是 | 行为语义，**18 类枚举之一**（见第五节表格） |
| `Data.Action.affect` | string | 是 | 情感语义（见第五节表情映射表） |
| `Data.Action.intensity` | number | 否 | 强度 **0~1**，用于选择动作变体（见第五节） |
| `Data.Action.priority` | number | 否 | 优先级，前端未使用（保留字段） |
| `Data.Action.matchedKeywords` | string[] | 否 | 触发关键词，前端未使用（保留字段） |
| `Data.Action.sentimentHint` | number | 否 | 情感提示，前端未使用（保留字段） |

⚠️ **提醒（前端代码注释原文）**：`Data.Lips` 存在是前端处理消息的**前提条件** —— 前端回调里是 `if (message.Data && message.Data.Lips)` 才进入处理分支，否则打印 "收到消息但没有Lips数据"。**所以即使某条消息没有音频，也建议带上至少 `[{ "Lip": "sil", "Time": 0 }]` 的 Lips 数组**，否则该条消息前端完全不处理（动作、表情、音频都不会执行）。

## 四、口型数据（Lips）协议 ⚠️

前端用 OVR LipSync 的 **15 种 viseme** 映射嘴部开合度（见 `lipsync.ts`）：

```json
"Lips": [ { "Lip": "aa", "Time": 120 }, { "Lip": "sil", "Time": 80 } ]
```

| 字段 | 说明 |
| --- | --- |
| `Lip` | 音素标识，**必须是下表中 15 种之一** |
| `Time` | **持续时间，单位毫秒** |

### 合法的 Lip 枚举（viseme → 嘴型开合度）

| Lip | 开合度 | 对应口型 |
| --- | --- | --- |
| `sil` | 0.0 | 静音/闭嘴 |
| `PP` | 0.2 | 双唇闭合 |
| `FF` | 0.3 | 下唇咬上齿 |
| `nn` | 0.3 | 舌尖抵上齿龈 |
| `TH` | 0.4 | 舌尖抵上下齿 |
| `SS` | 0.4 | 舌尖接近上齿 |
| `RR` | 0.4 | 舌尖卷曲 |
| `DD` | 0.5 | 舌尖抵上齿 |
| `CH` | 0.5 | 硬腭 |
| `ih` | 0.5 | 半张，前高元音 |
| `kk` | 0.6 | 舌根抵软腭 |
| `E` | 0.6 | 微张，前元音 |
| `oh` | 0.7 | 圆唇，后元音 |
| `ou` | 0.8 | 圆唇突出，后高元音 |
| `aa` | 0.9 | 张嘴，低元音 |

### ⚠️ 三条硬性提醒
1. **大小写敏感**：`PP`/`FF`/`TH`/`DD`/`SS`/`RR` 是大写，`kk`/`nn`/`aa`/`ih`/`oh`/`ou` 是小写。写错会被前端当作未知音素映射为 `0.0`（嘴巴不动）。
2. **`Time` 之和 ≈ 音频时长**：前端用 `Lips` 累加和作为 `durationMs`，用于音频播放的**超时兜底**（`max(3000, durationMs + 2500)` ms）。若 Time 与音频实际时长严重不符，会导致音频被提前切换或卡住。
3. **`Time` 是相对时长而非绝对时间戳**：前端按「依次累加」的方式定位当前音素。

## 五、动作 / 表情 / 情感 协议

前端动作决策顺序（见 `lappmodel.ts`）：

```
1. Action（behavior/affect/intensity）  ← 最高优先，推荐后端主力输出
2. MotionNo / MotionGroup               ← 兼容层，无 Action 时才用
3. Sentiment                            ← 兜底，前两者都没有时才用
```

### 1. Action 语义动作（推荐）

#### behavior（行为）→ TapBody 动作映射表 ⚠️

前端映射表见 `live2d-action-map.ts`，**behavior 必须使用以下 18 个枚举值之一**，否则前端找不到动作、直接忽略：

| behavior | 语义 | 候选动作下标 | 前端行为 |
| --- | --- | --- | --- |
| `nod` | 点头 | [1, 3] | 轻/重 |
| `invite` | 邀请 | [21] | - |
| `wave` | 挥手 | [10] | - |
| `reject` | 拒绝 | [2, 7] | 轻/重 |
| `think` | 思考 | [11, 12] | 轻/重 |
| `question` | 疑问 | [18, 12] | - |
| `explain` | 解释 | [22, 23] | 简述/详述 |
| `recommend` | 推荐 | [24] | - |
| `summary` | 总结 | [26] | - |
| `wait` | 等待 | [19] | - |
| `remind` | 提醒 | [20] | - |
| `warn` | 警告 | [25] | - |
| `thanks` | 感谢 | [17, 9] | 轻/重 |
| `apology` | 道歉 | [16, 17] | - |
| `care` | 关心 | [5, 9] | - |
| `celebrate` | 庆祝 | [6, 13] | 轻/重 |
| `surprise` | 惊讶 | [13, 14] | - |
| `sad` | 悲伤 | [15, 8] | 轻/重 |

⚠️ **intensity 决定变体选择**：当某 behavior 有 2 个候选时，前端计算
`index = round(clamp(intensity, 0, 1) * (候选数 - 1))`。
- 例：`behavior="nod", intensity=0.2` → 取下标 1（轻度）；`intensity=0.9` → 取下标 3（重度）。
- 后端应输出 `intensity` 在 **0~1** 之间，越界前端会自动截断。

#### affect（情感语义）→ 表情映射表

| affect | 表情文件 |
| --- | --- |
| `smile` / `warm` / `neutral` | F01（默认微笑） |
| `curious` / `surprised` / `excited` | F04 |
| `serious` | F02 |
| `sorry` / `sad` | F03 |

⚠️ 前端只认识上表 8 个 affect 枚举，其他值会被忽略（表情不切换）。

### 2. MotionNo / MotionGroup 兼容层 ⚠️

- `MotionNo` **从 1 开始计数**（前端内部 `targetMotionNo = motionNo - 1`），传 0 会落到动作 0。
- `MotionGroup` 缺省时前端使用 `TapBody`；若指定的组没有动作，前端自动回退到 `TapBody`。
- 传了 `Action` 时前端**优先用 Action**，MotionNo 被忽略。

### 3. Sentiment 情感兜底

范围 **-2（非常消极）~ +2（非常积极）**，前端映射规则：

| Sentiment | 表情 | 动作 |
| --- | --- | --- |
| `>= 1.5` | F04 | 随机 [6, 13]（庆祝/欢呼） |
| `>= 0.8` | F04 | 随机 [1, 3, 4]（点头/微笑/开心） |
| `>= 0.3` | F01 | 动作 1（点头） |
| `> -0.3` | F01（默认微笑） | 无动作（保持 Idle） |
| `<= -0.3` | F02 | 随机 [2, 7]（轻微不满） |
| `<= -0.8` | F02 | 动作 8（摇头） |
| `<= -1.5` | F03 | 随机 [8, 15]（沮丧） |

## 六、HTTP 音频服务要求 ⚠️

前端直接用 `new Audio(url)` 播放 `Data.HttpValue`，因此后端 TTS 音频服务必须满足：

1. **HTTP GET 可访问**：浏览器能直接请求到音频文件。
2. **CORS 支持**：前端页面与音频服务通常跨域（前端运行在 `localhost:5173`，音频在 `127.0.0.1:5000` 等），**必须返回 `Access-Control-Allow-Origin: *`**（或正确的来源），否则 `audio.play()` 静默失败。
3. **浏览器可解码的音频格式**：建议 WAV / MP3 / OGG。
4. **音频时长与 Lips 总时长一致**（见第四节第 2 条）。
5. ⚠️ **浏览器自动播放策略**：无用户交互时 `play()` 会被浏览器拦截（`NotAllowedError`）。前端已内置处理（队列暂停 + 显示 "Enable Audio" 解锁按钮 + 心跳恢复），**后端无需特殊处理，但应容忍音频消息在用户点击前不发声**；分片会被前端缓存，用户交互后自动补播。
6. 前端对每个分片有超时兜底（`durationMs + 2500ms`），超过会强制切下一段，因此**不要发送 URL 可访问但内容损坏/超时的音频**。

## 七、流式音频分片协议 ⚠️

前端实现了**流式多分片队列**（见 `lappmodel.ts` 的 `queueFayAudio`），一次回复可拆成多个 audio 分片依次下发。后端需要遵守：

- **`IsFirst: 1`**：标记新音频流的开始。⚠️ 前端收到后会：`streamId+1`、**清空旧队列**。旧的、未播完的分片（streamId 不匹配）会被前端标记为 stale 直接丢弃。
- 中间分片：`IsFirst: 0, IsEnd: 0`。
- **`IsEnd: 1`**：最后一个分片。⚠️ 前端收到后恢复默认表情 F01，且**不会立即打断正在播放的动作**（让动作自然播完）。
- 分片之间前端顺序排队播放，不重叠。
- ⚠️ **若前端中途（非 IsFirst=1 的 first 分片）接入流**，前端会自动创建默认 streamId=1 继续播，但**强烈建议第一条永远是 `IsFirst: 1`**。

## 八、前端内部硬编码 / 不可配置项（后端需知晓）

| 项 | 值 | 来源 |
| --- | --- | --- |
| WebSocket 地址 | `ws://127.0.0.1:10002` | `lappmodel.ts` |
| 握手 Username | `"User"` | `fayclient.ts` |
| 待机动作组名 | `Idle` | `lappdefine.ts` |
| 语义动作组名 | `TapBody` | `lappdefine.ts` |
| 口型参数 | `ParamMouthOpenY`（0~1） | `lappmodel.ts` / `lipsync.ts` |
| 表情命名 | `F01`~`F04`（对话结束恢复 F01） | `live2d-action-map.ts` / `lappmodel.ts` |

⚠️ **模型资源侧提醒**（详见 `docs/Live2D模型制作要求.md`）：
- `ParamMouthOpenY` 由前端**独占**驱动，动作/表情文件里**不要**对它设置关键帧，否则口型冲突。
- 动作组必须是 `Idle` + `TapBody`，TapBody 按数组下标索引。
- 表情命名必须 `F01`、`F02`... 格式。

## 九、验收清单（后端自查）

- [ ] 监听 `ws://127.0.0.1:10002`，接受 `{Username: "User", Output: true}` 握手
- [ ] 所有下发的消息为 JSON 文本帧，包含 `Topic` / `Username` / `Data`
- [ ] 每条语音消息 `Data.Key === "audio"`，且带 `Lips` 数组（即使空音频）
- [ ] `HttpValue` 指向 CORS 放行的、浏览器可播放的音频 URL
- [ ] `IsFirst`/`IsEnd` 正确标记分片边界；新回复首片 `IsFirst: 1`
- [ ] `Lips[].Lip` 全部在 15 个合法枚举内（大小写正确），`Time` 总和 ≈ 音频时长
- [ ] `Action.behavior` 在 18 个枚举内、`Action.affect` 在 8 个枚举内、`intensity` ∈ [0,1]
- [ ] 无 Action 时提供 `Sentiment`（-2~2）作为兜底，或提供 `MotionNo`（1 起）/`MotionGroup`
- [ ] 对话最后一条消息 `IsEnd: 1`
